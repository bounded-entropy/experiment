# Shared adapter definitions

ADR 0028 builds on ADR 0027's checkpoint and tensor-transfer services. An
`AdapterType.definition` is consumed by both `compile_replay` and
`compile_rollout`. All retained shared adapters and external recipe adapters enter through that interface. Their existing native compute, stochastic draws,
recorded context, parameter groups and checkpoint codecs remain providers
underneath it. Native vLLM LoRA still uses its native multi-LoRA path.

## Define a custom operation

An adapter module contains its state/operation declaration:

```python
from rlstack import (
    AdapterType, adapter_type, AdapterDefinition, Dim, Operation,
    Parameter, SiteKind, SiteProgram, Symbol,
)

@adapter_type("my_steer")
class MySteer(AdapterType):
    definition = AdapterDefinition(
        operation=Operation.CUSTOM,
        site=SiteKind.RESIDUAL,
        parameters=(Parameter("direction", (Dim.OUTPUT,)),),
        program=SiteProgram(
            forward=Symbol("my_package.math_torch", "forward"),
            reference=Symbol("my_package.math_torch", "reference"),
            helpers=(Symbol("my_package.math_triton", "add_kernel"),),
        ),
    )
```

Configure it with `AdapterSpec("my_steer", "resid_pre.10", init={"d": 4096})`,
using the model's actual boundary width. `resid_pre.10` retains its historical
meaning: the stream leaving layer 10. Linear sites derive input/output widths
from `SiteMeta.shape`, and can declare `Input.INPUT` as well as `Input.OUTPUT`.
Their widths need not match. Residual sites currently expose the output
stream, not the block's heterogeneous input argument tuple.

Shapes accept integer dimensions and `Dim.INPUT`/`Dim.OUTPUT`. Parameters
declare dtype, trainability and zero/one/seeded-normal initialization. Custom
`init` accepts only `seed` and boundary `d`; operation settings belong in the
typed definition, not unvalidated init metadata. A fixed-width operation may
declare `SiteProgram.width` instead of supplying `d`.

The compute functions have one signature:

```python
def reference(tensors, parameters, tokens):
    direction = parameters[0][tokens.slot]
    return (tensors.output + direction).to(tensors.output.dtype)
```

- `tensors.output`: `[current_tokens, output_width]`, the original logical
  vector to replace. `tensors.input` is available when requested at a linear
  site. Output shape, dtype and device must be preserved.
- `parameters`: declared tensors in declaration order, with a leading bank
  slot dimension. Triton can index that dimension directly with `tokens.slot`;
  the framework does not require materializing one parameter matrix per token.
- `tokens`: GPU columns `position`, `request`, `active`, `prefix_length` and
  `slot`. `request` is a current batch index, not a stable request identity.
  Kernels must mask inactive/padded rows and avoid invalid reads. The engine
  additionally preserves inactive output rows.

The forward can launch multiple Triton kernels, allocating temporary tensors
through PyTorch's capture allocator. It may not mutate its inputs or the
parameter banks. Declare helper source symbols so kernel edits enter code
identity. References provide CPU execution and the local autograd rule. GPU
training executes the forward and recomputes the reference for backward;
CPU training uses reference autograd directly. A forward-only declaration is
serving-only and is refused for a trainable bank entry.

Declare `ExperimentSpec.code=("my_package",)` and install that package in
the worker image. A serving build declares the same full source manifest with
`EngineBuild(code=load_code(("my_package",)), serves=("my_steer",))`. The custom
worker verifies that manifest and imports declared class modules before loading
implementations. Every explicit provider module must be covered by the roots. No code is dynamically downloaded or embedded in a
request. Importing `rlstack` itself remains free of torch, vLLM and Triton.

Two complete declaration-only examples ship in
`rlstack/policy/adapters/site_examples.py`: `site_steer` and fixed-rank
`site_lora16`. Their shared lifecycle is entirely generated by the common
replay/rollout lowerings. The existing `lora` adapter remains preferable for
native multi-LoRA serving; no throughput advantage is claimed for the example
Triton low-rank implementation.

## Serving lifecycle

Build an inference engine with the custom names in `serves`, as for existing
adapters. The `SITE` lowering selects `rlstack_engine.site_worker.SiteWorker`.
It installs persistent banks/hooks before vLLM's memory profile and accounts
for their allocation before KV-cache sizing. Native low-rank execution and
custom operations can share a model; logical q/k/v and gate/up views preserve
the physical packed base projection. Native LoRA wrappers are hooked once at
their output, rather than also hooking their inner base layer.

Before capture, dummy batches run the actual operations with all rows inactive.
On each real step the runner bridge updates routing after `_prepare_inputs`,
outside the captured model. Thus capture does not freeze a request's adapter
selection. Ordinary decode supplies only new query rows; old cached tokens
are not transformed again. A q/k/v projection operation affects that layer's
subsequent cache write; a decoder-output operation affects later layers.

ADR 0027 still chooses NCCL or base64 and owns checkpoint cadence. The custom
consumer retains transported tensors and passes local storage/CUDA IPC
handles to vLLM workers. It does not encode an archive to install them.
Every worker must acknowledge the exact bundle before its request generates.
Request holds govern retirement; an uncertain/cancelled install is also
retired before reuse. All custom types in one policy share a prefix cache salt for the immutable
full bundle, whose metadata includes their program definitions. Changing parameter versions never silently changes an
in-flight request's cache history.

## Qualification boundaries

The engine bridge is pinned to vLLM 0.28's V1 runner and currently refuses
TP/pipeline/DP widths above one, speculative execution, dual/microbatch overlap
and sleep-mode builds.
It exposes ordinary floating-point linear projections and the dense model
`model.layers.N`/`model.norm` residual boundaries. Quantized/deferred-bias
modules, embeddings, vocabulary heads and other model naming/layouts need
separate providers or qualification; unsupported payload sites are refused.
The existing native providers retain their previously supported modes.

The new interface currently supports parameter state and read-only token/
cached-prefix metadata. Writable per-request/recurrent state, an explicit
post-RoPE K/V staging site, historical cache edits and BPTT are future phases
of ADR 0028. They are not implied by the existence of the interface. Generic
programs currently use unit operation scaling; other coefficients can be
declared in their parameter state. Additional state scopes and operation
providers need explicit semantics and tests before admission.

CPU tests exercise real math, derivatives, tenant isolation, tensor IPC,
publication acknowledgements, state round trips, inactive rows, buffer
addresses and legacy identity. CUDA tests are hardware-gated. Neither a
passing CPU test nor source inspection certifies vLLM graph capture, IPC on
CUDA, mixed native/custom generation, memory sizing, or throughput. Those
remain a desk-based GPU drill with retained per-case predictions/tolerances,
version identities, phase timings, memory and trace evidence under AGENTS.md.

## Existing identities

`identity_compat.py` contains exact-source aliases for the lifecycle-only
extraction of existing adapter classes. Each key covers its new class source,
resolved declaration and direct provider module source. An edit changes the
key and receives a new identity. The historical `2432682289f4` regression is
unchanged, not rebased to a new literal. Old payloads/stores are not rewritten.
This is a narrow migration rule, not implementation of the broader source
closure work still proposed in ADR 0023.

A site can advertise multiple supported mechanisms, so native and custom
providers can coexist without failing Phase 0. RPC preserves scalar mechanism
rows for old single-provider cases and uses sorted lists for multiple providers.
The fake engine models `SITE` only when explicitly enabled in its plugins.

Recipe-specific native providers use `definition.native` with fully qualified
provider module names. DreamBank and task-indexed factual adapter variants now
live in the separate recipe repository; their state and transport contracts are
the same shared services. See [experiment ownership](experiment-boundary.md).
